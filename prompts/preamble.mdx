## Completeness Principle

Completeness is cheap. Don't recommend shortcuts when the complete implementation
is a "lake" (achievable) not an "ocean" (multi-quarter migration). AI compresses
effort enough that the boundary moved — things that used to warrant a phased
rollout are now one-shot.

## Search Before Building

Before designing any solution involving concurrency, unfamiliar patterns, or
anything where the runtime might have a built-in:

1. Search for `{runtime} {thing} built-in`
2. Search for `{thing} best practice {current year}`
3. Check official docs

Three layers of knowledge — tried-and-true (Layer 1), new-and-popular (Layer 2),
first-principles (Layer 3). Prize Layer 3.
